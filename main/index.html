      Network

      Uplink WiFi and a client network for simple Internet and tailnet access

      Device-wide network
      Used as DHCP Option 12 on every uplink and as the default Tailscale machine name.
      Rewrites the TTL hop-limit on every outgoing IPv4 frame on the STA side. Typical use: set to 64 to cloak a tethered downstream as the phone's own traffic when the upstream carrier throttles hotspot-detected packets. Applied live on save.
      Hostname applies at next reboot; TTL override is live immediately.
      Uplink networks
      —
      Currently connected —

      The router tries networks in priority order. If the top one can't be reached after a few retries, it rolls down to the next. Each network keeps its own IP configuration (DHCP or static).

      Save writes to NVS. A reboot is required to apply WiFi changes.
      Client WiFi / Tailnet gateway
      —
      This WiFi network lets devices use the ESP32 as their gateway to the Internet and to routes available through Tailscale. When switched off, it stays hidden during normal connected operation but returns automatically if the uplink is lost, so the router cannot become unreachable.
      Connected clients —
      Automatic — the AP follows the uplink WiFi channel. The ESP32-S3 has a single 2.4 GHz radio, so the access point and the uplink must share a channel.
      Also serves as DHCP server, default gateway, and DNS for connected clients.
      The DHCP pool is derived from this. /24 gives ~100 leases.
      DHCP Option 6 — what AP clients learn as their resolver. Empty hands out this device's own AP IP and routes lookups through the on-board forwarder below (the usual setup). Enter a LAN resolver such as Pi-hole to bypass the forwarder.
      On by default — forwards queries from AP clients to the upstream resolver below. Turn off only if a separate resolver (Pi-hole, external DNS server) is reachable on the AP subnet.
      Where the forwarder sends queries it cannot answer locally. Leave empty to follow the uplink DHCP lease, or enter a resolver on your LAN.
      Clients still need the SSID typed in to connect — this only stops casual scanners from listing it.
      Changing the AP SSID/password or IP will disconnect any clients (including this browser) at next reboot.
      DHCP reservations
      —

      Pin a fixed IP to a client MAC. The optional name shows up in the clients table below. Reservations apply at the next DHCP renew — reboot or reconnect the client to force one.

      Save replaces the whole table. Up to 16 entries.

      LAN → Tailnet Port Forwarding
      —

      Expose selected Tailnet services on the ESP32 uplink-LAN address. LAN clients do not need Tailscale and do not need to join the ESP32 access point. This table is fully separate from AP-side port forwarding.

      Source CIDRs filter addresses, not client identity. Use the narrowest subnet and keep authentication on the remote service. A mapping being installed does not prove the service is reachable.

      Loading saved rules and passive diagnostics…

      Service watch (optional periodic destination tests)

      Off by default. Tests one enabled TCP rule per interval through this gateway, using the same bounded handshake as Test destination. Two misses in a row send one ntfy/MQTT notice; the next answer sends a recovery notice. It never changes rules.

      Templates never enable a listener or save automatically. Enter the actual destination and a narrow source CIDR; verify service authentication and resolve any port conflict before enabling.

      Back up or import saved service rules

      Exports contain destination addresses/hostnames and source subnets, not credentials. Keep the file private. Import replaces this LAN → Tailnet table only, never the separate AP-side mappings. All imported rules start OFF; review before confirming.

      Export saved rules 
      No import preview.
      Temporary exposure and expiry

      Save the rules first. Timers require a synchronized clock, survive restart and do not enable a disabled rule. Reordering keeps the timer with its rule. After first timer use, new or edited bindings need explicit timer/permanent confirmation. Expired rules stay closed; optional deletion also releases their configured ports.

      Tunnel MTU
      —

      AUTO uses 1280 on both direct and relayed paths, matching the remote Tailscale tunnel and preventing oversized return packets from stalling downloads. TCP MSS is clamped to 1240. Fixed mode remains available for advanced setups. FIXED pins a user-supplied value in 576..1500. The effective MTU drives the WireGuard netif MTU, the AP-side TCP MSS clamp on every SYN, and the next-hop MTU reported in ICMP frag-needed replies.
