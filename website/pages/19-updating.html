Updating

An update keeps your settings. A fresh install erases them. Choose the update path unless you want to start over.

Over the air (recommended)

  1. Back up first: System → Backup.
  2. Upload firmware.bin in System → Firmware, or enable the opt-in GitHub update check there.
  3. The gateway writes the free slot, restarts into it and keeps the previous image. If the new image does not start correctly, it returns to the previous one.

The Ethernet variant updates only from firmware-eth.bin; the two images are never mixed.

From v2.0.0 or v2.0.1

Update once by hand: upload firmware.bin in System → Firmware, or use USB keeping settings. The built-in GitHub updater of those two versions restarts the gateway without installing anything; with automatic installation enabled it may do so at its install hour until you update. From v2.0.2 the GitHub update works again.

By USB, keeping settings

Use the browser installer with Erase device unticked, or UPDATE-KEEP-SETTINGS / install.sh update from the Easy Install package.

From 1.13 and earlier to v{{next_version}}

The v2 series uses product-own version numbers (see Versioning). Updaters in 1.10–1.13 only understand the older numbering and only the repository's previous name. The published migration used two steps:

  1. The 1.100 bridge release was published under the old repository name before the rename. Devices that installed it received the new updater.
  2. From the bridge, the device can find v{{next_version}} like a later update.

After the repository is renamed, devices still on 1.13 or older cannot find updates by themselves. Update them once by hand: upload firmware.bin in the Web UI, or use USB keeping settings. Settings, the tailnet identity and saved Wi-Fi carry over; the first-boot setup does not appear.
