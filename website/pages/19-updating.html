Updating

An update keeps your settings. A fresh install erases them. Choose the update path unless you want to start over.

Over the air (recommended)

  1. Back up first: System → Backup.
  2. Upload firmware.bin in System → Firmware, or enable the opt-in GitHub update check there.
  3. The gateway writes the free slot, restarts into it and keeps the previous image. If the new image does not start correctly, it returns to the previous one.

This works between 3.x versions. A 2.x gateway first moves to the 3.0 flash layout: see below.

From 2.x to 3.0

Firmware 3.0 uses a new 8 MB flash layout, so the 2.x updater does not offer it. Settings, the tailnet identity and saved Wi-Fi are kept on every path:

  1. Over the network: in System → Firmware update install 2.1.0, the migration bridge (a normal 2.x update). Turn on the web UI lock (System → Access → Require the admin password) and sign in — the migration needs it. Then System → Maintenance → Move to the 3.0 flash layout: tick the confirmation and press Migrate to 3.0. Keep the power on; it takes a few minutes and returns to 2.1.0 if 3.0 does not start.
  2. Over USB: the browser installer with Erase device unticked, or UPDATE-KEEP-SETTINGS / install.sh update from the Easy Install package.

Boards with 4 MB of flash cannot run 3.0 and stay on 2.x. Full guide: Moving a 2.x gateway to 3.0.

From v2.0.0 or v2.0.1

Update once by hand: upload firmware.bin in System → Firmware, or use USB keeping settings. The built-in GitHub updater of those two versions restarts the gateway without installing anything; with automatic installation enabled it may do so at its install hour until you update. From v2.0.2 the GitHub update works again; from 2.0.0 or 2.0.1 you can upload the 2.1.0 bridge directly.

By USB, keeping settings

Use the browser installer with Erase device unticked, or UPDATE-KEEP-SETTINGS / install.sh update from the Easy Install package.

From 1.13 and earlier to v{{next_version}}

Since v2 the firmware uses product-own version numbers (see Versioning). Updaters in 1.10–1.13 only understand the older numbering and only the repository's previous name. The published migration used two steps:

  1. The 1.100 bridge release was published under the old repository name before the rename. Devices that installed it received the new updater.
  2. From the bridge, the device can find v{{next_version}} like a later update.

After the repository is renamed, devices still on 1.13 or older cannot find updates by themselves. Update them once by hand: upload firmware.bin in the Web UI, or use USB keeping settings. Settings, the tailnet identity and saved Wi-Fi carry over; the first-boot setup does not appear.
