Troubleshooting

Work from the bottom layer up: uplink, tailnet control, peer path, rule, application. The Web UI reports each layer separately.

The device does not join the tailnet

  • The auth key is expired, ephemeral or single-use and already consumed: create a reusable, non-ephemeral key.
  • Headscale: check the login server URL and that its certificate comes from a public CA.
  • Tailnet lock is enabled: it is not supported.

It was working and dropped off after months

Node-key expiry was left enabled. Disable it in the admin console and reboot the ESP32 once.

Tailnet clients cannot reach the LAN

Approve the advertised route in the admin console. If LAN hosts have no route back to 100.64.0.0/10, enable source NAT for advertised routes.

A Service Gateway rule does not work

  1. Run Test destination. If it fails, the peer is offline, the port is closed or the peer ACL does not allow the ESP32.
  2. Check that the rule is enabled and not expired, and that the client's address is inside the source CIDR (rejected counter).
  3. Check the client points at the ESP32's address and listen port, not at the remote service.

I cannot reach the Web UI

  • Use the IP address or the .local name; other host names are refused when no password is set.
  • If the saved WiFi is gone, wait 60 seconds and join the ESP32's recovery access point.
  • Too many failed logins pause sign-in briefly; wait instead of retrying repeatedly.

The updater says the GitHub check failed

Check Internet access and the time of day (TLS). Firmware 1.13 or older cannot follow the repository rename: update once manually with firmware.bin.

Export a diagnostic report (System → Diagnostics), review it for private details, and open an issue. Full guide: docs/TROUBLESHOOTING.md.
