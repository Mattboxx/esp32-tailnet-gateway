Recovery and device management

  • Wake-on-LAN address book (up to 12 devices) from the Web UI, MQTT, Home Assistant or replay-protected ntfy commands.
  • Bounded Smart Recovery jobs: precheck a known port, one WoL burst, wait, check again.
  • The recovery access point can make the Web UI reachable if the saved Wi-Fi is unavailable.

Monitoring and diagnostics

  • Per-rule state, accepted/rejected counters, admitted replies and the last evidence seen.
  • Destination test (one bounded TCP handshake) and opt-in Service watch with change alerts.
  • Route explain, ping, traceroute, WiFi scan, live logs, optional microSD flight recorder, sanitized diagnostic export.

Configuration and management

  • Responsive Web UI and JSON API; PBKDF2 password verifier with login challenge, sessions, cross-site and DNS-rebinding screening.
  • Configuration profiles (Gateway, Recovery, IoT, Monitoring, Advanced) with preview and rollback.
  • Encrypted configuration backup and restore; opt-in GitHub updates with application rollback.
  • No telemetry, crash uploads or forced update polling.

Automation and integrations

Optional possible-blackout MQTT events and Home Assistant Discovery support power-return automations, with per-boot identity, duplicate suppression and retained diagnostics for catch-up. Software restarts and brief network disconnects do not produce this event.

MQTT with Home Assistant Discovery, ntfy alerts and commands, Telegram and email (SMTP) notifications, read-only SNMP v1/v2c. Each is supervised and off by default; none can block routing or local administration. See Automation.
