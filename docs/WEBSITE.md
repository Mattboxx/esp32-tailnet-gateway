# Website, SEO and indexing

The project website is a static site generated by `tools/build_site.py` from
`website/` (page fragments and CSS/JS) plus `assets/brand` and
`assets/diagrams`. No framework, analytics, cookies, web fonts or third-party
scripts; a strict Content-Security-Policy allows only same-origin resources.

## Build and preview

```bash
python tools/build_site.py --check          # build/site + link/SEO/a11y checks
python -m http.server -d build/site 8000    # http://localhost:8000/
node tools/test_site_browser.cjs            # 9 viewports, needs Playwright
node tools/test_site_installer_mobile.cjs   # Phone fallback + desktop installer
```

`--check` fails on broken internal links, missing repository files, more or
fewer than one `h1`, skipped heading levels, missing `alt`, duplicate titles
or descriptions and pages missing from the sitemap. The browser test checks
320–1920 px and landscape phone widths for page overflow, text size, 44 px
touch targets, the mobile menu, search and console errors.
The installer regression also removes Web Serial in phone-emulated contexts
to exercise the actual unsupported-browser slot, in light and dark themes.
It checks a single readable notice panel and preserves the supported desktop
button. This is Chromium rendering coverage, not a physical iOS/USB flash test.

## What each page gets

Distinct title and description, canonical URL, Open Graph and Twitter card
with the 1280×640 social preview, breadcrumb (with `BreadcrumbList` data),
`SoftwareApplication` + `WebSite` data on the home page and `FAQPage` data on
the FAQ. `sitemap.xml`, `robots.txt`, `site.webmanifest`, a `404.html` and
small redirect pages for alternative URLs (`lan-to-tailnet/`, `install/`, …)
are generated. Search runs locally from `search-index.js`.

## Languages

English is primary. Pages declare `lang`; an Italian tree can be added as
`website/pages/it/` with `hreflang` alternates once every page is translated.
No partial translation is published.

## Publishing (owner authorization required)

`.github/workflows/pages.yml` runs only on manual dispatch. Pages is published
from `Main` at `https://mattboxx.github.io/esp32-tailnet-gateway/` after the
repository rename. `NEXT_VERSION` selects the versioned installer; its files
must remain byte-identical to the released package. Presentation-only changes
do not rebuild firmware or replace release assets. CSS URLs include a content
hash so returning visitors receive the matching layout after a deployment.

## Search engines

1. Google Search Console: add a URL-prefix property for the site URL, verify
   using a supported verification method, then submit `sitemap.xml` under
   *Sitemaps*. A verification file must be explicitly included in deployment;
   the builder does not automatically publish arbitrary extra directories.
2. Bing Webmaster Tools: import from Search Console or verify with the same
   method; submit the sitemap.
3. Monitor *Pages* / *Coverage* reports for excluded or failing URLs. A
   sitemap does not guarantee indexing or ranking.

Keyword themes covered by page content (no invented search volumes): ESP32
Tailscale, ESP32 Tailnet gateway, ESP32 Headscale, ESP32 subnet router,
Tailscale IoT gateway, LAN to Tailnet, Tailnet port forwarding, devices without
a Tailscale client, Tailscale Wake-on-LAN, ESP32 remote recovery, Tailscale
ESP32-S3, ESP32 Home Assistant.

For performance and accessibility reviews, run Lighthouse against the deployed
site and retain the execution records with the private validation logs.
