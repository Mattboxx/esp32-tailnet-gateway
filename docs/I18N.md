# Web UI languages

The embedded Web UI, including the first-boot setup, ships in **English,
Italiano, Español, 简体中文, Français and Deutsch**. English is the source
language and the fallback. The language is detected from the browser
(`navigator.languages`) and can be changed in **System → General → Interface
mode → Language**, or with the picker at the top of the setup wizard; the
choice is stored only in that browser (`localStorage`), never on the device.

## How it works

- Dictionaries live in `main/i18n/<code>.json` as `{ "English text": "translation" }`
  and `main/i18n/languages.json` lists the languages that are built in.
- `main/gen_index_html_gz.py` turns each dictionary into one small script,
  `i18n/<code>-<hash>.js`, embedded gzip-compressed next to the page. Keys are
  FNV-1a hashes of the English text (the English already ships in the page);
  a hash collision fails the build. The page itself carries only the list of
  languages.
- A loader at the top of the page asks for the visitor's language as early
  as possible and keeps the page hidden until it arrives (at most 2.5 s, then
  English), so nothing flashes in English first. Only that one language is
  downloaded; its name changes with its content, so the browser keeps it
  until the firmware changes (`Cache-Control: immutable`).
- At run time the UI replaces whole text nodes, `placeholder`/`title`/
  `aria-label` attributes and `confirm()` messages whose English text matches
  a key. A `MutationObserver` translates content rendered later. Keys
  containing `{}` are patterns for sentences assembled at run time
  (`Last updated {}`); the value in `{}` is copied unchanged.
- Typed values, addresses, ports, keys and anything inside `code`, `pre`,
  `textarea` or `[data-no-i18n]` are never changed.

## Coverage (honest numbers)

`python tools/i18n_extract.py --coverage` measures the extracted strings:
every language covers all 1689 at this checkpoint. Product names and
technical terms (SSID, MAC, CPU, Tailscale, GPIO names, example addresses)
are kept as they are on purpose. Sentences assembled from several run-time
pieces without a pattern stay English. Validation fails below 90 %.

## Size and speed

Measured on 3.0.1-beta.1: the page is about 156 KB gzip (it was about 230 KB
with three languages inside it) and each language script about 33 KB gzip,
loaded only when used. Languages live in the firmware image (3.5 MB update
slots, about 2.2 MB used), not in the storage area: they take nothing from
the event history, trends or settings copies, and no RAM until a browser asks
for one (served straight from flash). The page itself is sent with an ETag,
so an unchanged firmware answers a reload with an empty `304`.

The 2.1 migration bridge stays English only to fit a 1920 KB 2.x slot.

## Adding or fixing a translation

1. `python tools/i18n_extract.py` refreshes `main/i18n/source.json`.
2. Edit `main/i18n/<code>.json`; keep numbers, units, `/32`-style values,
   `tskey-auth-…` and similar tokens exactly as in English.
3. A new language also needs an entry in `main/i18n/languages.json`.
4. Run `python tools/i18n_extract.py --coverage` and the browser suites
   (`test_automation_ui.cjs`, `test_ui_layout.cjs`, `test_first_boot_ui.cjs`,
   which runs the wizard in every language); check narrow phones (320 px) for
   long words.
